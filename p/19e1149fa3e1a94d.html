antirez의 ds4 (DwarfStar): DeepSeek V4 Flash 전용 로컬 추론 엔진

70추천도 실용성 18/25 · 신규성 9/15 · 최신성 4/10 · momentum 8/10
깊이 12/15 · 지속가치 12/15 · 신뢰도 7/10

핵심 포인트

무엇인가
  • Redis를 만든 antirez가 DeepSeek V4 Flash를 1순위 타깃으로 잡은 네이티브 추론 엔진 DwarfStar(저장소명 ds4)를 공개했다. GLM 5.2와, 초고용량 머신에서는 DeepSeek V4 PRO도 지원한다.
  • 범용 GGUF 러너가 아니다. 모델 로딩, 프롬프트 렌더링, 툴 콜, KV 상태, HTTP 서버, 코딩 에이전트를 한 덩어리로 같이 만들고 같이 테스트한다는 것이 설계 전제다.
  • 백엔드는 Metal(주 타깃, 96GB 이상 맥), NVIDIA CUDA(멀티 GPU·DGX Spark), Strix Halo 계열 ROCm. 공개 3개월이 지난 지금도 활발히 커밋되고 있고 별 2만 개를 넘겼다.
  • GGML에 링크하지는 않지만 llama.cpp가 뚫어놓은 길·커널·양자화 포맷 위에 서 있다고 README가 먼저 밝힌다. GGUF quant 레이아웃, CPU quant/dot 로직, 일부 커널은 MIT로 가져다 썼다.
핵심 설계 판단: 비대칭 양자화
  • 2비트 quant를 쓰지만 전부 2비트로 내리지 않는다. 라우팅되는 MoE expert만 양자화하고(up·gate는 IQ2_XXS, down은 Q2_K), shared expert·projection·라우팅은 손대지 않는다.
  • 근거가 명확하다. routed expert가 모델 용량의 대부분을 차지하니 거기서만 깎으면 용량은 크게 줄고 품질에 민감한 부분은 원본으로 남는다. 그래서 2비트인데도 코딩 에이전트를 붙이고 툴 콜을 안정적으로 돌릴 수 있다고 주장한다.
  • 가져갈 멘탈 모델은 이것이다. 양자화는 모델 전체에 균일하게 적용할 하이퍼파라미터가 아니라, 용량 기여도와 품질 민감도가 다른 텐서군마다 따로 정하는 문제다.
실측 수치 (Metal CLI, ctx 32768, greedy)
  • MacBook Pro M5 Max 128GB · q2: 짧은 프롬프트 prefill 87.25 t/s, 생성 34.27 t/s. 11707토큰 프롬프트에서는 prefill 463.44 t/s, 생성 25.90 t/s.
  • MacBook Pro M3 Max 128GB · q2: 짧은 프롬프트 prefill 58.52 t/s, 생성 26.68 t/s. 두 세대 차이가 prefill에서 특히 크게 벌어진다.
  • Mac Studio M3 Ultra 512GB에서 PRO q2를 32768토큰으로 돌리면 prefill 138.82 t/s, 생성 9.56 t/s. 큰 모델을 얹는 대가가 생성 속도로 정확히 돌아온다.
  • DGX Spark GB10 128GB · q2(7047토큰): prefill 343.81 t/s, 생성 13.75 t/s. prefill은 맥과 비슷한 급인데 생성이 절반 아래다.
  • 구형 CUDA 카드 재활용 사례도 있다. vLLM이 신규 모델 지원을 끊은 Ada Lovelace 세대 8xL40S 서버에서 ds4-server 마이크로 배칭으로 합산 생성 120 t/s, prefill 2000 t/s의 사내 다중 사용자 서버를 만들었다고 한다.
RAM보다 큰 모델을 돌리는 방법
  • SSD 스트리밍 모드가 있다. non-routed 가중치는 메모리에 상주시키고 routed MoE expert만 메모리 캐시에 두다가 미스 때 GGUF 파일에서 읽는다. `./ds4 -m ./ds4flash.gguf --ssd-streaming`으로 자동 예산부터 시작한다.
  • 특성을 알고 써야 한다. 긴 prefill은 여전히 빠를 수 있지만 생성은 캐시 미스에 훨씬 민감하다. 토큰마다 다시 expert를 타기 때문이다. 64GB 맥이면 2비트 Flash GGUF에 중간 크기 expert 캐시로 시작하라고 권한다.
  • `--ssd-streaming-cache-experts 32GB`는 바이트 캐시가 아니라 routed expert 메모리 예산이다. 스트리밍 prefill용 두 개 레이어분 헤드룸을 먼저 떼고 남은 바이트를 expert 슬롯 수로 환산한다. 반면 숫자만 주면(`4000`) 정확히 그 슬롯 수를 뜻한다.
기기를 붙여 쓰기: 링크 품질이 전부다
  • 파이프라인 병렬(레이어를 기기에 쪼개기)과 RDMA 텐서 병렬을 지원한다. Mac Studio 두 대로 PRO Q4 전체를, MacBook 두 대로 GLM 5.2를 돌리는 레시피가 README에 그대로 있다.
  • 같은 M5 Max 두 대·같은 91GB Flash quant·8192토큰으로 링크만 바꾼 비교가 결론을 준다. Thunderbolt 5(ping 0.45ms) prefill 582.99 t/s·생성 25.09 t/s, WiFi(77.20ms) 250.70·10.70, 인터넷 VPN(152.10ms) 114.88·3.63.
  • 즉 레이턴시는 생성을 직접 때리고 대역폭은 긴 prefill을 끌어내린다. 분산 추론을 검토한다면 케이블부터 정하는 것이 맞고, VPN 구성은 인터랙티브용이 아니라 '어차피 한 대엔 안 올라가는 모델을 그래도 열어보는' 용도다.
네이티브 에이전트: 세션 = 디스크 KV 캐시
  • 추론을 에이전트 안에서 직접 제어한다. 소켓·API 경계가 없고, 세션 그 자체가 디스크에 있는 KV 캐시다(`~/.ds4/kvcache`). 그래서 KV 캐시 불일치가 구조적으로 불가능하다고 말한다.
  • 체감 이득은 레이턴시다. 생성 텍스트 표시·툴 콜·새 세션 시작이 즉시고, prefill 진행 바가 보이며, `/save` `/list` `/switch <sha>`로 저장 세션을 prefill 없이 복원한다. `/strip`은 대화 텍스트만 남기고 무거운 KV를 버린다.
  • DSML 같은 중간 툴 콜 변환이 없고 시스템 프롬프트·툴이 이 모델에 맞춰 수직 설계됐다. 대가는 이식성이며, 저자도 나중에 서버·클라이언트를 쪼개 상태 유지 프로토콜로 갈 가능성이 있다고 적어뒀다.
품질을 지키는 장치
  • `ds4-eval`은 리더보드가 아니라 회귀 스위트다. 내장 92문항(GPQA Diamond 25, 감수한 SuperGPQA 25, AIME 2025 25, CVE에서 축약한 C/C++ 취약 라인 찾기 COMPSEC 17)으로 커널·양자화·프롬프트 렌더링·KV·툴 스트리밍을 바꿨을 때 실제 사용자 경로가 여전히 푸는지 본다.
  • 92/92를 기대하지 말라고 명시한다. 뒤쪽 문항은 강한 추론 모델도 일부 놓치게 일부러 배치했다. `--temp 0 --seed 1`로 q1..q4 생성 토큰 수를 고정 기준과 맞추는 결정론적 게이트가 진짜 회귀 감지 장치다.
  • `ds4-bench`는 전체 평균 대신 컨텍스트 프론티어(2048, 4096, 6144 ...)별 순간 처리량을 잰다. KV 상태를 스냅샷·복원하며 새로 추가된 구간만 측정하므로, 긴 컨텍스트에서 어디부터 느려지는지가 보인다.
  • 저자가 AI 사용을 먼저 공개한다. GPT 5.5·5.6·Claude Fable의 강한 보조로 개발했고 아이디어·테스트·디버깅은 사람이 주도했다고 적었다. 이 규모의 저수준 코드가 어떻게 3개월 만에 나왔는지에 대한 답이기도 하다.
읽을 때 걸러야 할 것
  • 원문 X 게시물의 '대기업이 수십억 태운 GPU 클러스터를 뒤집었다' 프레이밍은 프로젝트가 하는 주장이 아니다. README의 목표는 소비자 하드웨어에서 쓸 만한 오픈 웨이트 모델을 돌리는 것이고, 데이터센터 대비 우위를 주장하지 않는다.
  • 'C 파일 하나 몇천 줄' 프레이밍도 현재 저장소와 맞지 않는다. 지금 `ds4.c` 한 파일이 2.9MB이고 Metal·CUDA·서버·에이전트·eval이 별도 파일로 붙어 있다. 단일 파일이라는 미학보다 '모델 몇 개만 노린 좁은 수직 통합'이 실제 포인트다.
  • 진입 장벽이 낮지 않다. Metal 경로는 96GB 이상 맥이 기준이고(그 아래는 SSD 스트리밍), 저자 스스로 베타 품질에 매우 빠르게 변한다고 못 박았다. 지원 GGUF 목록도 고정이라 임의 GGUF는 안 열린다.
  • 모델 지원이 의도적으로 기회주의적이다. 128GB 노트북·512GB 워크스테이션급에서 가장 좋은 오픈 웨이트를 따라가며, 더 나은 대체가 나오면 기존 모델을 제거할 수 있다고 밝혀뒀다. 장기 고정 런타임으로 깔 대상은 아니다.
