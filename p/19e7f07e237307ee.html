코드베이스를 지식 그래프로: Understand Anything vs CodeGraph

70추천도 실용성 22/25 · 신규성 8/15 · 최신성 4/10 · momentum 8/10
깊이 10/15 · 지속가치 12/15 · 신뢰도 6/10

핵심 포인트

한 줄로
  • 둘 다 코드베이스를 지식 그래프로 바꿔 AI 에이전트에 먹이는 도구인데, 그래프를 '누가' 만드느냐가 정반대다. Understand Anything은 LLM 멀티에이전트가 만들고, CodeGraph는 Rust·tree-sitter 파서가 만든다. 이 한 가지 차이에서 비용·정확도·용도가 전부 갈린다.
Understand Anything · LLM이 그래프를 만든다
  • Claude Code 플러그인으로 설치하고 `/understand` 한 번이면 파일·함수·클래스·의존관계를 훑어 `.ua/knowledge-graph.json`을 만든다. 대시보드에 레이어별 색상 그룹, 퍼지·시맨틱 검색, 의존 순서대로 정렬된 가이드 투어, diff 영향 분석까지 붙어 있다.
  • 진짜 값어치는 시각화가 아니라 온보딩 쪽이다. `/understand-onboard`는 신규 입사자용 가이드를, `/understand-domain`은 코드가 아니라 업무 도메인·플로우·스텝을 뽑아준다. 파서가 원리적으로 못 하는 게 정확히 이 '의미' 계층이다.
  • 대가는 토큰이다. 최초 `/understand`는 코드베이스 전체를 LLM으로 분석해서 큰 프로젝트에선 상당량을 태운다. 이후는 변경 파일만 증분 분석. README가 '구독 플랜에서 돌리거나 초기화는 로컬 모델(Ollama 등)로 하라'고 따로 안내할 정도.
  • 6월 이후 소유가 Lum1104 개인에서 Egonex-AI 조직으로 넘어갔다. MIT는 유지, 대신 상용 홈페이지와 라이브 데모가 붙었다. 개인 실험 프로젝트가 아니라 제품 쪽으로 방향을 잡았다고 보는 게 맞다.
CodeGraph · 파서가 그래프를 만든다
  • Rust 커널이 tree-sitter 문법으로 20개 언어를 파싱해 심볼·호출 엣지·의존을 뽑고 로컬 SQLite(FTS5)에 넣는다. LLM 호출이 아예 없고 100% 로컬, API 키 불필요. OS 네이티브 파일 이벤트(FSEvents·inotify)로 2초 디바운스 자동 싱크라 인덱스가 낡을 일이 없다.
  • MCP 도구를 일부러 하나(`codegraph_explore`)만 노출한다. '좁은 도구 여러 개보다 강한 도구 하나가 에이전트를 덜 헤매게 하고 세션 컨텍스트를 아낀다'는 측정 결과에 따른 선택이고, 나머지 7개는 환경변수로만 켠다. 도구 설계 관점에서 그대로 훔쳐올 만한 결정이다.
  • 커버리지를 주장하지 않고 측정해서 표로 깐다. Python(requests) 100%, Go(gin) 96.6%, Rust(ripgrep) 86.7%, Liquid(Shopify dawn) 73.8%. 남는 부분은 런타임 동적 디스패치·리플렉션·DI 컨테이너처럼 정적 분석의 진짜 한계라고 명시하고, 분모를 손대서 숫자를 예쁘게 만들지 않았다고 못박는다.
메일에 적힌 수치는 지금 기준으론 어긋난다
  • 메일 원문은 '토큰 57%, 도구 호출 62% 절감'이라고 적었는데, 저장소의 2026-08 재측정값은 '평균 비용 44%, 토큰 62% 절감'이다. 57~78%는 평균이 아니라, 파일 탐색 에이전트가 28~43번 도구를 호출해야 겨우 답하는 탐색 난도 높은 질문에서만 나오는 구간값이다.
  • 절감폭은 저장소 크기가 아니라 질문이 요구하는 '탐색량'을 따라간다. 7번 호출로 풀리는 질문에선 차이가 거의 없다. 도입 효과를 추정할 땐 레포 규모 말고 팀이 주로 던지는 질문 유형을 봐야 한다는 뜻.
덜 알려진 트레이드오프
  • CodeGraph는 처리 토큰은 줄이지만 컨텍스트 잔류량은 오히려 늘린다. 같은 7개 벤치 저장소 멀티턴 세션에서 세션 종료 시점 잔류 검색 컨텍스트가 파일 탐색 방식보다 약 80% 많았다(VS Code 기준 67k 대 18k). 한 번에 밀도 높은 답을 통째로 반환하고 그게 창에 계속 남기 때문이다.
  • 그래서 '토큰 아끼는 도구'가 아니라 '왕복을 줄이는 도구'로 이해하는 게 정확하다. 컨텍스트 창이 좁고 세션이 길면 이 잔류량을 예산에 넣고 시작해야 한다. 저장소가 이 불리한 지표를 스스로 공개한다는 점 자체가 신뢰 근거이기도 하다.
고를 때 기준
  • 낯선 코드베이스를 '사람'이 이해해야 하면 Understand Anything, '에이전트'가 매 턴 정확한 컨텍스트를 받아야 하면 CodeGraph. 목적이 겹치지 않으니 같이 쓰는 것도 말이 된다.
  • 다만 둘 다 프로젝트마다 인덱스 디렉터리를 만든다(`.ua/`, `.codegraph/`). gitignore 처리와 팀 공유 여부는 붙이기 전에 정해두는 게 좋다. 특히 Understand Anything은 그래프를 커밋해서 공유하는 걸 전제로 별도 뷰어까지 제공한다.
