Claude Code 세션 40만 건 분석: 성공을 가른 건 코딩 경력이 아니라 도메인 전문성

64추천도 실용성 12/25 · 신규성 12/15 · 최신성 4/10 · momentum 6/10
깊이 12/15 · 지속가치 12/15 · 신뢰도 6/10

핵심 포인트

연구 설계
  • Anthropic Economic Research가 2026-06-16 공개. 2025년 10월부터 2026년 4월까지 Claude Code 인터랙티브 세션 약 40만 건, 사용자 약 23만 5천 명을 privacy-preserving 방식(Clio)으로 분석했다.
  • 성공의 정의가 느슨하지 않다. 테스트 통과나 커밋처럼 검증 가능한 증거가 남은 세션만 성공으로 센다. '만족스러웠다' 같은 자기보고가 아니다.
  • 세션을 9개 work mode로 분류한 뒤 자동 수집 telemetry(코드 추가·삭제 라인 등)와 교차검증. 코드 생성·수정으로 분류된 세션의 90% 이상이 telemetry에서도 실제 코드 변경을 보였다.
분업 구조
  • 평균적으로 기획 결정(무엇을 할지, 어떤 접근을 쓸지, 무엇을 완료로 볼지)의 약 70%는 사람이, 실행 결정(어떤 파일을 고칠지, 어떤 코드·언어·명령을 쓸지)의 약 80%는 Claude가 가져간다.
  • 전형적인 세션은 약 4턴. 프롬프트 1개가 평균 10개 내외의 Claude 액션 체인을 촉발하고, 많으면 100개를 넘는다. 한 턴에 평균 2,400단어를 쏟아낸다.
  • 누가 결정하느냐가 곧 위임량이다. 사용자가 실행 결정을 80% 넘게 붙들면 턴당 약 8액션, Claude가 기획까지 80% 넘게 쥐면 약 16액션. 통제를 놓는 만큼 에이전트가 일한다.
여기서 전문성의 정의
  • 직함이 아니라 task 단위 전문성이다. Rust를 처음 만지는 시니어 엔지니어는 그 작업에서 초보고, 파이썬을 써본 적 없어도 마감 정산에서 어떤 규칙이 지켜져야 하고 어디서 엣지케이스가 틀어지는지 짚는 회계사는 그 작업의 전문가다.
  • 분류기가 보는 신호 3개: 지시를 얼마나 정밀하게 프레이밍하는가, 무엇을 검증하라고 요구하는가, 사용자가 Claude를 교정하는가 아니면 Claude가 사용자를 교정하는가.
  • 이 3개 신호는 그대로 체크리스트로 쓸 수 있다. 검증 기준을 프롬프트에 박는 행위 자체가 '전문가 세션'의 관측 가능한 표식이라는 뜻이다.
전문성이 산출량을 바꾼다
  • 초보 세션은 프롬프트당 약 5개 액션·600단어, 전문가 세션은 약 12개 액션·3,200단어. 액션은 2배 이상, 산출은 5배다. 같은 한 줄을 던져도 아는 사람이 던지면 에이전트가 다섯 배를 일한다.
  • 이 격차는 모든 work mode와 모든 task value 구간에서 나타나며 p<0.001. work mode·task value·월·직업·모델군을 통제한 회귀에서도 전문성 한 단계당 액션 +9%, 산출 +13%로 유지된다(표준오차는 사용자 단위 클러스터링).
성공률: 직업은 거의 못 가른다
  • 실제로 코드를 만든 세션만 추려 직업별 성공률을 보면 소프트웨어 엔지니어 34%, 다른 직업 29%. 5%p 격차가 7개월 내내 좁혀지지도 벌어지지도 않았다.
  • 상위 10개 직업이 전부 엔지니어와 7%p 이내. 변호사·회계사·마케터·디자이너가 개발자와 거의 같은 비율로 일을 끝냈다.
  • 대신 전문성이 갈랐다. 초보로 분류된 세션의 성공률 15%, 전문가는 그 2배 이상. 단 중급과 전문가 사이 격차는 작아서, 이득의 대부분은 초보에서 중급으로 넘어가는 구간에서 나온다.
  • 막혔을 때의 이탈도 갈렸다. 초보는 19%가 코드 한 줄 없이 포기했고 나머지 구간은 5~7%. 실력 차이보다 오류에서 복구하는 능력 차이로 읽힌다.
7개월 동안 일의 모양이 바뀌었다
  • 디버깅에 쓰인 세션 비중이 거의 절반으로 줄었다(포스트 표기로는 33%에서 19%). 그 자리를 배포·실행, 데이터 분석, 문서 작성이 채웠다.
  • 현재 구성: 코드 작성 25%, 수정 26%, 테스트·오케스트레이션 5%로 코드 직접 작업이 56%. 소프트웨어 운영 17%, 계획·탐색 14%, 분석·산문 13%.
  • 프리랜스 구인 공고와 비교해 추정한 task value가 거의 모든 종류의 일에서 올랐고 평균 약 25%. 에이전트가 더 복잡하고 값나가는 일을 맡기 시작했다는 신호다.
  • 배경 수치로 GitHub 프로젝트 중 coding agent 활동이 있는 비중이 2025년 말 대비 2배 이상, Claude Code 사용자의 평균 사용 시간은 주 20시간.
원문 대조에서 어긋난 지점
  • 포스트는 task value 상승을 27%로 적었지만 원문은 about 25%다. 큰 차이는 아니지만 인용할 때는 25%를 쓰는 게 맞다.
  • 실행 결정 비중을 '클로드가 80%'로 읽으면 정확하다. 원문은 사람이 실행 결정의 20%만 한다고 서술한다.
  • 직업별 34%·29%와 초보 15% 수치는 원문 후반부(크롤 상한 밖) 구간이라 이 레터에서는 포스트의 인용을 따랐다. 앞부분 수치는 모두 원문에서 직접 확인했다.
실무로 가져갈 것
  • 결론을 '코딩 몰라도 된다'로 읽으면 정반대다. 문제를 정확히 아는 사람이 에이전트를 더 많이·더 정확히 일하게 만든다는 이야기고, 그 지식은 코딩 지식이 아니라 도메인 지식이다.
  • 당장 바꿀 수 있는 습관 하나: 프롬프트에 '무엇을 검증할지'를 명시하기. 분류기가 전문성으로 읽는 신호이자, 검증 증거로 성공을 정의한 이 연구에서 성공률과 직결되는 지점이다.
  • 익숙하지 않은 영역에 에이전트를 붙일 때는 전문가가 되려 애쓰지 말고 중급까지만 끌어올리는 게 비용 대비 효율이 가장 크다. 이득 대부분이 초보에서 중급 구간에 몰려 있다.
  • 선행 연구로 자율성 측정 리포트와 Anthropic 내부 업무 변화 리포트가 있고, 전문성 분류 예시는 공개 데이터셋 SWE-chat 세션에서 가져왔다.
