Cursor 코드베이스 인덱싱 해부: 결과를 가르는 건 모델이 아니라 검색이다

71추천도 실용성 15/25 · 신규성 12/15 · 최신성 5/10 · momentum 7/10
깊이 13/15 · 지속가치 13/15 · 신뢰도 6/10

핵심 포인트

핵심 주장
  • 코딩 에이전트 품질을 가르는 변수는 모델 지능이 아니라 '무엇을 읽힐지 고르는 능력'(retrieval)이다. 같은 모델에 시맨틱 검색을 붙였을 때 Cursor 자체 평가에서 응답 정확도가 평균 12.5%, 최대 23.5% 올랐다.
  • 즉 인덱싱은 눈에 안 보이는 보조 기능이 아니라 대형 코드베이스에서 에이전트 성패를 결정하는 1차 요인이다.
검색기 2개를 서로 대체하지 않는다
  • 시맨틱 검색(뜻으로 찾기, "결제 재시도하는 부분")과 렉시컬 검색(글자 그대로 찾기, "이 함수를 호출하는 모든 자리")은 상호 대체 불가. 전자는 정확한 패턴을 못 집고, 후자는 의미를 모른다.
  • 배치 위치까지 다르다. 시맨틱 인덱스는 서버, 렉시컬 검색은 로컬. 근거는 신선도 요구가 다르다는 점이다. 시맨틱은 좀 낡아도 방향만 맞으면 쓸 만하지만, 렉시컬은 에이전트가 방금 자기가 쓴 코드를 못 찾으면 즉시 헤매기 시작한다.
  • 대형 코드베이스에서 ripgrep은 모든 파일을 한 줄씩 훑어야 해서 한 번에 15초를 넘기는 경우가 흔하다. 그래서 로컬에 별도 색인을 두고 항상 최신으로 유지한다.
인덱스 갱신: 머클트리
  • 파일마다 해시를 찍고 폴더 해시는 하위 파일 해시를 합쳐 만든다. 파일 하나를 고치면 그 파일과 상위 폴더 해시만 바뀌므로, 해시가 달라진 가지만 따라 내려가면 변경분을 특정할 수 있다. Git과 블록체인이 쓰는 그 머클트리다.
  • 파일 5만 개 워크스페이스의 파일명 + 해시 전체는 약 3.2MB. 매번 통째로 주고받는 대신 다른 가지 몇 개만 비교하는 구조로 동기화 비용을 접었다.
초기 인덱싱 비용을 없앤 방법
  • 신규 사용자에게 인덱스를 처음부터 만들어주지 않고 동료의 인덱스를 복사해 출발점으로 쓴다. 한 회사 안에서 같은 코드를 받아 쓰는 사본들은 평균 92%가 동일하다는 관찰이 근거.
  • 효과: 가장 큰 코드베이스 기준 첫 검색까지 4시간 넘게 걸리던 것이 21초로 줄었다. 차이 나는 부분만 뒤에서 따라 맞춘다.
공유가 만든 보안 구멍을 해시로 막다
  • 인덱스를 공유하면 내가 접근 권한이 없는 코드가 검색 결과로 새어 나올 수 있다. Cursor는 '파일을 실제로 가진 클라이언트만 그 파일의 해시를 제시할 수 있다'는 성질을 권한 증명으로 썼다.
  • 검색 결과를 돌려줄 때 클라이언트가 해당 파일 해시를 제시하지 못하면 그 결과를 제거한다. 내 로컬에 실제로 존재하는 코드만 검색에 걸리고, 서버는 원본 코드가 아니라 해시만 대조한다.
찾은 걸 컨텍스트에 다 밀어넣지 않는다
  • 검색 결과를 한 번에 모델에 전부 주지 않고 파일로 적어둔 뒤 에이전트가 필요한 부분만 꺼내 읽게 한다. 컨텍스트가 꽉 차는 문제와, 정보가 많을수록 모델이 오히려 헷갈리는 문제를 동시에 피하는 설계.
  • MCP 도구를 많이 붙인 환경에서 이 방식으로 에이전트 토큰 사용량을 46.9% 줄였다.
검색 모델을 에이전트의 실패 기록으로 학습
  • 남의 임베딩 모델을 그대로 쓰지 않고 직접 학습시킨다. 교재는 에이전트의 과거 작업 궤적. 한 작업을 끝낼 때까지의 검색·파일 열기 기록을 되짚으면 '원래 어느 코드를 맨 먼저 꺼냈어야 했는지'가 드러난다.
  • 검색의 기준 자체가 바뀐 게 핵심이다. '두 코드가 의미상 닮았나'에서 '지금 이 작업에 어느 코드가 실제로 도움이 됐나'로. 사후 오답노트를 다음 실행의 정답 라벨로 쓰는 구조.
관통하는 관찰
  • 새로 발명한 부품이 사실상 없다. 머클트리(Git·블록체인), 렉시컬 색인(1993년 논문과 2012년 Google Code Search 계보), 해시로 데이터를 가리키는 방식 모두 수십 년 된 기술이다. Cursor가 한 일은 이 부품들을 에이전트 워크로드에 맞게 재조립한 것.
  • 시사점: 에이전트 인프라에서 경쟁 우위는 신기술이 아니라 '기존 자료구조를 어느 제약에 맞춰 조립했는가'에서 나온다.
내 작업에 옮길 것
  • 에이전트 성능이 아쉬울 때 모델을 바꾸기 전에 retrieval을 먼저 본다. 같은 모델에서 12.5~23.5%가 움직인 지점이 거기였다.
  • 의미 검색과 패턴 검색을 하나로 합치려 하지 말고 둘 다 두고, 신선도가 중요한 쪽(패턴 검색)만 로컬에서 항상 최신으로 유지한다.
  • 대량 결과는 컨텍스트에 직접 붓지 말고 파일로 떨어뜨린 뒤 필요할 때 읽히는 패턴을 기본값으로 삼는다(토큰 46.9% 절감 사례).
  • 재색인 비용이 문제면 전체 재스캔 대신 해시 트리로 변경분만 추적하는 구조를 검토한다.
