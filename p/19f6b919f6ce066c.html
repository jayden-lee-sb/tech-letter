바이브코딩 말고 진짜 엔지니어링, Matt Pocock의 skills 레포 해부

71추천도 실용성 20/25 · 신규성 9/15 · 최신성 5/10 · momentum 8/10
깊이 11/15 · 지속가치 12/15 · 신뢰도 6/10

핵심 포인트

무엇인가
  • TypeScript 교육자 Matt Pocock이 자기 .claude 폴더를 통째로 공개한 스킬 모음 레포. 5개월 만에 GitHub 스타 17만을 넘기며 일간 트렌딩에 오름
  • 스킬 = 에이전트에게 '뭘, 어떤 순서로, 어떤 가드레일을 지키며 할지'를 정해주는 작은 작업 설명서. 시스템 프롬프트가 '뭘 아는지'를 준다면 스킬은 '어떻게 일할지'를 준다
  • Claude Code 전용이 아니라 Codex, Cursor 등 어떤 에이전트에서도 동작하는 모델 중립 설계
설계 철학
  • GSD, BMAD, Spec-Kit 같은 무거운 프레임워크는 프로세스를 통째로 소유해 편한 대신 통제권을 뺏고, 틀어졌을 때 고치기 어렵다는 진단
  • Matt은 반대로 '작게, 조합 가능하게, 어떤 모델에서도 되게'. 직접 뜯어고쳐서 네 것으로 만들라는 원칙
  • 배포 방식도 철학이 둘로 갈림. npx skills add로 파일을 프로젝트에 복사해 마음껏 고치거나, Claude Code 플러그인으로 읽기 전용 구독해 업데이트를 자동으로 따라가거나
대표 스킬 grill-me
  • 방향을 뒤집은 스킬. 내가 AI에게 질문하는 게 아니라 AI가 나를 심문한다. '이 경우는 어떻게 처리할 거예요?', '왜 이렇게 정했어요?'를 한 번에 하나씩, 애매한 게 없어질 때까지
  • 만들기 전에 사람의 의도를 또렷하게 정렬하는 장치. 이 스킬 하나가 레포 바이럴의 기폭제가 됨
AI 코딩 4대 실패모드 대응
  • 원한 걸 안 만든다 → grill로 먼저 정렬 / 너무 장황하다 → 프로젝트 용어를 CONTEXT.md에 정리
  • 코드가 안 돌아간다 → tdd 스킬로 실패 테스트 먼저 작성 / 진흙탕 코드가 된다 → 설계를 매일 조금씩 손질
  • 전부 오래된 엔지니어링 기본기라는 점이 핵심. AI 시대라고 기본기가 바뀌지 않더라는 실증
운영 팁
  • 스킬을 두 종류로 구분. 이름을 직접 불러야 도는 스킬(grill-me처럼 판을 짜는 것)과 에이전트가 알아서 집는 스킬(tdd, 코드리뷰 같은 규율)
  • 자동 발동 스킬은 매번 컨텍스트를 차지하므로 '꼭 자동이어야 하나'를 따져 아껴 쓰라는 게 실전 포인트
  • 기본 워크플로우는 아이디어 → 스펙 → 티켓 쪼개기 → 구현. 구현 중엔 TDD, 커밋 전엔 코드리뷰가 붙는 구조
