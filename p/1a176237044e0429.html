핵심 포인트

무엇인가
  • Chrome 개발자 경험 총괄 Addy Osmani가 공개한 AI 코딩 에이전트용 스킬 25개 묶음 (GitHub 별 11만 개 돌파)
  • DEFINE → PLAN → BUILD → VERIFY → REVIEW → SHIP 6단계 라이프사이클에 스킬을 배치, 각 단계 진입점은 /spec · /plan · /build · /test · /review · /ship 슬래시 커맨드
  • Claude Code, Codex, Cursor, Gemini CLI, Copilot 등 거의 모든 에이전트에 설치 가능 (스킬은 그냥 Markdown이라 이식성이 높음)
스킬 설계 원칙 (훔쳐 쓸 포인트)
  • Process, not prose: 참고 문서가 아니라 단계 · 체크포인트 · 종료 조건이 있는 워크플로로 작성
  • Anti-rationalization 표: '테스트는 나중에' 같은 에이전트의 흔한 핑계와 반박을 스킬마다 명시해 단계 건너뛰기를 막음
  • Verification 필수: 모든 스킬이 테스트 통과 · 빌드 출력 · 런타임 데이터 같은 증거 요구로 끝남, '맞아 보인다'는 불인정
  • Progressive disclosure: SKILL.md가 진입점이고 체크리스트 등 보조 자료는 필요할 때만 로드
눈여겨볼 스킬
  • interview-me: 한 번에 한 질문씩 캐물어 '진짜 원하는 것'을 약 95% 확신까지 끌어냄 (요구사항이 흐릴 때)
  • doubt-driven-development: 중요한 결정을 새 컨텍스트에서 반대 입장으로 검토 (CLAIM → EXTRACT → DOUBT → RECONCILE → STOP), 필요하면 다른 모델로 교차 검증
  • constraint-driven-development: 품질 기준을 CONSTRAINTS.md로 박고, 에이전트가 체크를 끄거나 테스트를 건너뛰어 green을 만드는 행태를 잡아냄
  • /build auto: 플랜을 한 번 승인하면 태스크 사이의 사람 개입만 없애고, 태스크별 TDD와 개별 커밋은 그대로 유지
도입 팁
  • npx skills add addyosmani/agent-skills --list 로 먼저 훑고, 필요한 스킬만 --skill 로 골라 설치
  • 단일 스킬 설치 시 repo 루트의 references/ 체크리스트는 따라오지 않음 (issue #361), 체크리스트까지 쓰려면 전체 설치나 clone
  • Claude Code에서는 내장 /review와 이름이 겹치므로 /agent-skills:review 처럼 네임스페이스 형태로 호출
  • 기존 코드베이스라면 Adoption Guide의 '검증 우선 점진 도입' 경로부터 시작하는 게 안전
비판적으로 볼 점
  • 롤백 스킬은 장애 때만 실행돼 평소 happy path로는 검증이 안 됨 (댓글 지적)
  • 이전 빌드 재배포는 코드만 되돌리고 상태는 못 되돌림: 이미 돈 마이그레이션 · 비워진 큐 · 외부 쓰기는 그대로라 '구 코드 + 신 스키마' 조합이 생김
  • 그래서 expand/contract 마이그레이션과 한가한 날의 롤백 리허설이 있어야 ship 단계가 실제로 안전해짐
  • 원 Threads 글 자체는 소개 수준이라, 실질 가치는 repo의 SKILL.md 본문을 직접 읽어야 나옴
