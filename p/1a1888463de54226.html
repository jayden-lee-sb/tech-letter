Cursor·xAI 개발자 Lauren Tan: 한 달에 PR 2,000개를 프로덕션에 반영한 워크플로우

76추천도 실용성 20/25 · 신규성 10/15 · 최신성 6/10 · momentum 8/10
깊이 11/15 · 지속가치 13/15 · 신뢰도 8/10

핵심 포인트

핵심 주장
  • 처리량은 에이전트 개수가 아니라 신뢰에서 나온다. 신뢰 = 아무도 안 볼 때도 결과물이 받아들일 만한 상태
  • 에이전트 하나도 못 믿는데 100개를 띄우면 쓰레기만 늘어난다. 1~5개 대화를 감독하는 단계부터 시작해 신뢰 곡선을 올리는 게 순서
  • 비유는 소프트웨어 공장이 아니라 미슐랭 주방. 사람은 헤드 셰프, 에이전트는 라인 쿡
교정의 5단 사다리 (강한 층에 고칠 것)
  • 1층 코드베이스·아키텍처: 나쁜 패턴을 범주째 불가능하게. 코드베이스가 곧 메모리라 안티패턴은 바이러스처럼 퍼진다
  • 2층 정적 분석(lint·컴파일러·CI): 기술 부채엔 먼저 lint 규칙으로 출혈을 막고, 기존 코드는 그다음 에이전트로 청소
  • 3층 rules·Bugbot·skills: 강제가 아니라 안내라 에이전트가 건너뛸 수 있다
  • 4층 스타일 가이드·사람 리뷰: 같은 리뷰 코멘트가 반복되면 아직 위층으로 못 올린 신호
  • 5층 검증 skill: 기능이 끝까지 동작하는지를 증명 (성능·품질 증명은 아님)
바로 가져다 쓸 기법
  • 에이전트는 지름길을 좋아하니 지름길을 정답 경로로 만든다 (Dune 프레임워크). 예: 주석 금지, 핵을 주석으로 변명하던 습관 차단
  • Electron main 프로세스 코드를 renderer에서 import 못 하게 의존성 그래프로 강제. 프레임 예산 60fps 약 16ms 기준
  • 검증 skill이 가장 중요: Chrome DevTools Protocol 기반으로 앱을 직접 띄우고 CPU trace·heap snapshot까지 찍게 한다
  • feature map(기능별 진입 경로·단축키·DOM selector)을 skill에 두고 automation으로 최신화. 없으면 에이전트가 헤맨다
  • eval = 에이전트용 unit test. 중립 이름 디렉터리에서 실행(평가받는 걸 눈치채면 행동이 바뀜), 다른 모델 judge로 교차 채점
  • PStack: 본인 디버깅·빌드 습관을 묶은 Cursor 플러그인 skill 모음, 오픈소스
실패 모드와 주의점
  • 코드·trace를 안 읽고 원인을 자신 있게 단정하는 환각 진단
  • 1~3층 없이 Slack·Sentry 이벤트로 클라우드 에이전트를 자동 기동하면 automation이 나쁜 PR을 증폭한다
  • PR 수치는 자기보고이고 출처마다 1,000·2,000·2,500으로 엇갈린다. 숫자보다 구조를 가져갈 것
